# Sopor v2, fas 1–2 – implementationsplan

> **För agenter:** Använd superpowers:executing-plans. Stegen använder checkboxar.

**Mål:** Sökning och schema för EDP-kommunerna (cirka 25 källor, 45–55 kommuner) bredvid de statiska kommunerna, med ett enda sökfält, beräknade datum och röda dagar i kalendern.

**Arkitektur:**
- Ett källregister ersätter kommunregistret. En källa (`avesta`, `vafab` …) täcker en eller flera kommuner och har ett system (`static`, `edp`).
- Ett statiskt gatuindex från OpenStreetMap säger vilka källor en gata kan finnas hos.
- Vercel Functions (`api/sok.ts`, `api/schema.ts`, `api/ics.ts`) är proxy och cache mot EDP.
- Webbläsaren pratar fortfarande bara med `WasteProvider`.

**Stack:** som v1, plus Vercel Functions (Web-standard `export default { fetch }`) och Overpass API för gatuindexet.

**Spec:** `docs/specs/2026-10-30-sopor-hela-sverige-design.md` (v2) och `docs/specs/2026-10-30-sopor-design.md` (v1).

## Globala krav

- Ingen kommunväljare. Ett sökfält.
- Inga källor bakom inloggning eller apptoken. User-Agent: `Sopor/1.0 (+https://sopor.hardyson.se)`.
- Befintliga URL:er och ICS-sökvägar för Avesta (`/avesta/<id>`, `/ics/avesta/<id>.ics`) ändras inte.
- Beräknade datum märks alltid "beräknat", både i UI:t och i ICS-filen.
- Tester går aldrig mot live-servrar. Sparade svar ligger i `src/providers/edp/__fixtures__/`.
- `npm run lint && npm test && npm run build` är grönt efter varje uppgift.

## Granskningsfokus

1. En EDP-källa som svarar långsamt, med fel eller med HTML får inte fälla sökningen. Övriga träffar visas. → Test i T6.
2. Samma gatuadress med flera byggnads-id (flerbostadshus) visas som separata träffar med särskiljare. → T5.
3. `WastePickupsPerYear` = 0 eller "enligt körlista" ger bara nästa datum, utan beräkning. Ogiltigt datum (`0001-01-01`) hoppas över. → T4/T5.
4. Ett beräknat datum på en röd dag får en varning men flyttas inte. → T4.
5. `/api/*` får inte skrivas om till `index.html` av SPA-rewriten, och `/ics/<källa>/<id>.ics` för live-källor går till `api/ics`. Avestas statiska filer ska fortsätta serveras. → T6/T10.

### T2: Källregister i stället för kommunregister

**Filer:** `src/municipalities/index.ts` → `src/sources/index.ts`, alla användningar, `src/domain/types.ts`

```ts
export interface Kommun { code: string; name: string }            // SCB-kod, "Avesta kommun"
export type SourceConfig = { system: 'static' } | { system: 'edp'; baseUrl: string }
export interface Source {
  id: string                 // URL-segment, t.ex. "avesta", "vafab"
  name: string               // "Avesta Vatten och Avfall"
```

- UI-texter som "Just nu: Avesta kommun" byggs av alla källors kommuner, sorterade och utan dubbletter.
- **Tester:** alla befintliga tester uppdateras till de nya namnen. Ett test kontrollerar att alla källors id är unika och URL-säkra (`/^[a-z0-9-]+$/`).

### T4: Beräknade datum

**Fil:** `src/domain/recurrence.ts` (+test)

```ts
export function expandPickups(input: {
  next: string                 // YYYY-MM-DD
  perYear: number              // 52, 26, 13, 104 …
  weekdays?: number[]          // 1=mån … 7=sön, bara för 104
  months?: number              // standard 12
}): { date: string; estimated: boolean; warning?: string }[]
```

- `next` får `estimated: false`. Följande datum får `estimated: true`.
- Steg: 52 → 7 dagar, 26 → 14, 13 → 28, 104 → båda veckodagarna varje vecka, och övriga värden → bara `next`.
- Ett datum som är en röd dag eller en afton får `warning: "Infaller på <namn> – kan flyttas."`. Ett bekräftat datum får ingen varning.
- **Tester:** 26/yr från 2026-11-11 ger 2026-11-25 och 2026-12-09. 52/yr från 2026-12-17 ger 2026-12-24 med varningen julafton. 104 med mån och tor. 0/yr ger bara next. Gränsen vid 12 månader.

### T5: EDP-klient (server)

**Filer:** `src/server/edp.ts` (+test), `src/server/fractions-map.ts` (+test), `src/server/http.ts`

```ts
export interface EdpBuilding { raw: string; street: string; locality: string; buildingId: string }
export function parseBuilding(raw: string): EdpBuilding | null      // "Storgatan 1, Grillby (909273)"
export function edpAddressId(b: EdpBuilding): string                 // "storgatan-1-grillby-909273"
export async function edpSearch(baseUrl: string, q: string, fetchFn?: typeof fetch): Promise<EdpBuilding[]>
export async function edpSchedule(baseUrl: string, raw: string, fetchFn?: typeof fetch): Promise<Schedule>
export function mapWasteType(text: string): { fraction: FractionId; label?: string }
```

- `http.ts`: `fetchJson(url, init, { timeoutMs })` med User-Agent och AbortController. Vid HTML-svar eller icke-JSON kastas `SourceError`.
- Schemat:
  - Tjänster grupperas per datum till `PickupEvent` med fraktioner och etiketter.
  - `expandPickups` (T4) körs per tjänst.
  - Veckodagarna för 104 tas ur `WastePickupFrequency` (måndag–söndag, även i plural).
  - `updatedAt` är dagens datum.
- `mapWasteType`:
  - rest: `restavfall`, `RESTAVFALL`
  - mat: `matavfall`
  - papper: `pappersförp`
  - plast: `plastförp`
  - glas: `glasförp`
  - metall: `metallförp`
  - tidningar: `tidningar`
  - allt annat (`Kärl 1`, `Fyrfack 1`, `FNI Kärl 1` …): `karl` med labeln trimmad, till exempel `Kärl 2 – Fyrfack` om frekvenstexten säger fyrfack.
  - `Slam`, ogiltigt datum och `perYear` 0 utan datum hoppas över.
- **Tester mot fixtures:**
  - `parseBuilding` för alla fixturer, inklusive "Storgatan, Byske (126649)" utan nummer
  - sök i Uppsala och Vafab
  - schema för Uppsala (8 tjänster med jämn/udda vecka), Örebro (104/yr, "Måndag, Torsdag") och SSAM ("enligt körlista", 0/yr, så bara next)
  - HTML-svar ger `SourceError`

### T6: API-funktioner och lokal utveckling

**Filer:** `api/sok.ts`, `api/schema.ts`, `api/ics.ts`, `src/server/handlers.ts` (+test), `vite.config.ts`, `vercel.json` (+test)

- Logiken ligger i `handlers.ts` och är testbar utan Vercel:
  - `handleSearch(url)`: `?q=…&sources=vafab,uppsala`. Den frågar bara EDP-källor bland `sources`, parallellt, med en timeout på 3 s per källa. Svaret är `{ addresses: Address[], failed: string[] }`.
  - `handleSchedule(url)`: `?source=&id=` hämtar adresssträngen via `edpSearch` på byggnads-id:t och gatan ur id:t, och returnerar `Schedule`.
  - `handleIcs(url)`: `buildIcs` med `estimated`-märkning.
- `api/*.ts`: `export default { fetch: (r) => handleX(new URL(r.url)) }`.
- Cache: sök `public, s-maxage=86400, stale-while-revalidate=604800`, schema och ICS `s-maxage=21600, stale-while-revalidate=86400`, och fel `no-store`.
- `vite.config.ts`: dev-middleware som skickar `/api/<namn>` till `handleX` via `server.ssrLoadModule`, så att `npm run dev` fungerar utan `vercel dev`.
- `vercel.json`:
  - SPA-rewriten undantar `api/`.
  - Ny rewrite `/ics/:source/:file` → `/api/ics?source=:source&file=:file`, som bara slår till när ingen statisk fil finns.
  - Headers för `/api/ics` (`text/calendar`).
- **Tester:** `handleSearch` med en källa som tar för lång tid, en som kastar och en som svarar, vilket ger träffarna plus `failed`. Rewrite-tester i `vercel-config.test.ts` för `/api/sok` och `/ics/vafab/x.ics`.

### T7: Gatuindex från OpenStreetMap

**Filer:** `scripts/build-street-index.ts` (+test för den rena delen), `data/osm/<kommunkod>.json` (checkas in), `public/data/gator/*.json` (genereras vid build), `scripts/build-data.ts`

- Skriptet tar kommunkoderna från `SOURCES` och frågar Overpass per kommun:
  ```
  area["ref:se:kommun:kod"="<kod>"]->.k; (way(area.k)[highway][name]; node(area.k)[place~"city|town|village|hamlet|suburb|neighbourhood|locality"][name];); out tags;
  ```
  Det sparar `{ code, streets: string[], places: string[] }` i `data/osm/<kod>.json`. Det körs manuellt (`npm run build:streets`) eller av en kvartalsvis GitHub Action som öppnar en pull request. Det väntar 2 s mellan anropen.
- `build-data.ts` läser `data/osm/*.json` och skriver ut:
  - `public/data/gator/<två första tecken>.json` med `{ [normaliserat gatunamn]: sourceId[] }`
  - `public/data/orter.json` med `{ [sourceId]: { [normaliserad ort]: kommunnamn } }`
- Ren funktion `buildStreetIndex(osm, sources)` med test: två kommuner med samma gata ger båda källorna, och en ort mappas till rätt kommun.
- Attribution: "Gatunamn © OpenStreetMaps bidragsgivare (ODbL)" på Om-sidan och i README.

### T8: Klienten – sök och schema över alla källor

**Filer:** `src/providers/api.ts` (+test), `src/providers/registry.ts` (+test), `src/ui/search/AddressSearch.tsx`

- `createApiProvider(source)` implementerar `WasteProvider` mot `/api/schema?source=&id=` och `icsUrl` → `/ics/<källa>/<id>.ics`. `getAddress` tolkar id:t (gata, ort och byggnads-id) utan nätverk.
- `searchAll(q)`:
  1. Ladda gatuindexets delfil för de två första tecknen i den normaliserade frågan (cachad).
  2. Ta fram källorna.
  3. Statiska källor söks lokalt, och EDP-källor i ett enda `/api/sok`-anrop.
  4. Slå ihop resultaten.

  Finns inte gatan i indexet frågas bara de statiska källorna.
- Delresultat: `{ addresses, failed }`. AddressSearch visar raden "Vafab Miljö svarar inte just nu" under träffarna.
- Träffraden visar kommunen (`address.kommun`) som chip.
- **Tester:** sök där indexet ger två källor ger bara de källorna i anropet. En okänd gata ger bara de statiska. En källa som fallerar visas som rad.
